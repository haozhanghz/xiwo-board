# 数位板（XPPen）适配说明

## XPPen 驱动是怎么工作的

分析对象：`XPPenTablet.app` 4.0.21（`com.ugee.PenTablet`，Qt 5.12，x86_64 + arm64 通用二进制）。
只做了静态分析（字符串、导入符号、反汇编、随附的配置和语言文件），没有复制或改写其中的代码。

- **这个包是设置面板，不是出笔事件的驱动。** 它引用的后台驱动是
  `/Library/Application Support/PenDriver/XPPenDriver.app`（触控型号另有 `XTouchDriver.app`），这两个程序不在这个压缩包里，
  所以下面关于笔事件的部分是从面板和配置推断的，没有在真机上抓过事件。
- 面板和后台驱动之间用 **Apple Events** 通信：按创建者签名找到驱动进程，发 `tBcl` 类事件，带 4 字节命令码和参数
  （改工作区、压感、橡皮模式、快捷键等都走这条路）；另外用分布式通知 `PenTabletDriverUX` 发按键状态。
- 面板自己还用开源的 hidapi 直接和数位板的厂商 HID 接口通信（读写固件配置、LED、屏幕校准），
  并用 `CGEventPost` 发键盘和媒体键（快捷键映射到按键时）。它不发笔事件。
- 面板里没有引用任何 DriverKit / kext / 系统扩展，也没有给第三方应用的 SDK 或私有通道。
  应用能拿到的就是系统标准的数位板事件：带 `tabletPoint` 子类型的鼠标事件（压感、倾斜、设备号）
  和 `tabletProximity` 事件（靠近板面的是笔尖还是橡皮）。
- 每支笔的配置（`config.xml`）：压感曲线 `P0 / P1X / P1Y / P2`（默认线性）、`DisablePressure`、
  `DisableSlope`（侧锋/倾斜）、绝对/相对坐标，以及笔键动作。默认笔键动作是「橡皮擦」「右键单击」「双击」
  （`Actid` 27 / 207 / 209，对照随附的语言文件）。配置可以按应用单独设置（`<Apps><app path>`）。

结论：XiwoBoard 和 XPPen 之间唯一的接口是 AppKit 的数位板事件，优化应当做在 XiwoBoard 这一侧。

## 为什么会觉得写字不够顺

1. **事件合并**：AppKit 默认把连续的拖动事件合并，数位板每秒上报两三百次，应用只拿到一部分点，曲线变成折线。
   （由书写流畅度的改动处理：用画笔写字时关闭 `NSEvent.isMouseCoalescingEnabled`，并改成局部重绘。）
2. **抬笔前的零压力**：笔离开板面前的最后一两个采样压感接近 0，毛笔会拖出一个细尖尾巴；偶发的掉点也会让线条突然变细。
3. **压感抖动**：相邻采样压感差几个百分点，不合并之后每个点都用上，毛笔边缘会发毛。
4. **笔迹跟不上笔尖**（0.1.11 及以前）：书写中的笔迹由画布自己在 CPU 上重画。每来一个笔点，画布重画笔迹末尾那一小块，
   再把整个画布（全屏时二十多 MB）重新提交给系统合成，主线程每个点要花 2 ms 多；画布每次屏幕刷新又最多重画一次。
   在 60 Hz 屏幕上，笔点从产生到出现在屏幕上平均约 41 ms。

## XiwoBoard 里做了什么

- `PenPressureFilter`（XiwoCore）：压感低于 0.02 视为抬笔或掉点，沿用上一个值；其余做轻度指数平滑；结果限制在 0.05…1。
- `TabletInput`：全局监听 `tabletProximity`（独立事件和鼠标事件里的子类型两种形式都认），记下橡皮的设备号。
  - 选着画笔时，把笔翻过来用笔尾就直接擦除，工具栏的选择不变。只有设备号和橡皮一致的落笔才擦除，
    所以鼠标不会误擦；笔尖重新进入感应范围、或切到别的应用时，橡皮状态都会清零。
  - 如果驱动把设成「橡皮擦」的笔键报告成橡皮设备，按住这个键写也是擦除（取决于驱动，没在真机上验证）。
- 笔侧键：XPPen 默认有一个笔键是「右键单击」。选着画笔时，按住这个键划过就是擦除，松开继续写；
  一次按住算一步撤销。用鼠标右键仍然和以前一样（编辑时弹出菜单）。
- 书写中的笔迹（0.1.12 起）画在画布上面的一层透明 Metal 图层里（`LiveInkView`）。每个笔点只把新增的线段
  （`InkTessellator`，和最终的 Core Graphics 线条同样的平滑曲线、线宽和笔帽）交给一个独立的渲染线程，由 GPU 重画整笔，
  画好就交给系统合成，下一次屏幕刷新显示；画布在写字过程中不动。抬笔时画布从页面图像里补画这一小块，Metal 图层
  等这次提交送出以后才清空，两者在同一帧上屏，所以抬笔时笔迹不会闪一下。
  没有 Metal 的 Mac 自动用旧的画法；也可以运行 `defaults write io.github.haozhanghz.xiwoboard MetalInk -bool NO`
  手动切回旧画法（重开应用生效，`defaults delete io.github.haozhanghz.xiwoboard MetalInk` 恢复）。
- 硬笔的笔锋（0.1.13 起）见下面的[笔锋](#笔锋)。
- 延迟可以用 `XiwoBoard --ink-latency` 实测：它在全屏授课页面上模拟 240 Hz 的数位板写字，统计每个笔点从事件产生到
  出现在屏幕上的时间，并检查抬笔交接有没有闪烁或重影。

这些行为用合成的数位板事件在 Apple 芯片 Mac 上跑过（写字、笔尾擦除、鼠标不误擦、侧键擦除、撤销）。

## 笔锋

希沃白板 Mac 版的普通笔迹和 XiwoBoard 一样粗细不变，带笔锋的字来自它设置里的「书写美化」：每个笔点交给一个运行时从希沃服务器
下载的 WebAssembly 模块算出轮廓再填充。这个模块没有拿来用，也没有照着它仿（希沃的工程师公开写过，这套做法有专利）。XiwoBoard 的笔锋是按
钢笔写字的规律自己做的（XiwoCore 的 `PenNib`），参数是第一版，可以再按手感调：

- **快细慢粗**：笔速按屏幕上的距离算（视图点每毫秒），先平滑约 18 ms，再换成粗细：写得慢约 1.18 倍笔宽，
  每毫秒 1 个点以上约 0.72 倍，中间平滑过渡；用数位板时再乘上压感（0.7 + 0.6 × 压感）。粗细本身再平滑约 10 ms，
  不会一个点一跳。速度按屏幕算，所以放大缩小画布写出来一样。
- **出锋**：抬笔时看最后约 12 ms 笔还在不在走。还在走（每毫秒 0.2 个点以上），就把这一笔最后一段收成笔尖：
  长度按抬笔时的速度算，最多 7 个笔宽，也不超过这一笔的七成，末端细到 0.1 倍。停住 25 ms 以上再抬笔，或者写得慢，
  末端保持圆头。
- **怎么画**：每个点的粗细存在笔迹里（`StrokePoint.widthScale`，文件里是 `w`，保留三位小数）。写字时 GPU 把每一小段画成
  两头圆、粗细渐变的一段（`InkTessellator` 和着色器），抬笔后页面用 Core Graphics 把同样的这些小段合成一个形状填充，
  所以抬笔时线条不跳，只有出锋那一段在抬笔时收细。在一台 M3 的 Mac 上模拟 240 Hz 数位板写字，开关笔锋的书写延迟
  一样（平均约 19 ms），抬笔多花约 1 ms。
- 笔锋默认开着，在笔的设置里取消「笔锋」就回到粗细一致的硬笔，设置会记住。毛笔和荧光笔不受影响，以前写的笔迹也不变。
- 0.1.12 及更早的版本打开带笔锋的笔迹会忽略粗细，画成粗细一致的线；导出 `.enbx` 时笔锋不保留，导出前会列出来。

## 推荐的 XPPen 设置

- 在 XPPen 设置里为 XiwoBoard 单独加一个应用配置，压感曲线保持默认线性，平滑交给 XiwoBoard。
- 上课时把屏幕映射设成投影或一体机所在的显示器，避免笔和光标错位。
- 想用侧键擦除，就保留其中一个笔键为「右键单击」。

### 板上快捷键

授课时 XiwoBoard 认这些键，XPPen 的快捷键设成对应的按键就能用：

| 按键 | 作用 |
| --- | --- |
| E | 在橡皮和笔之间切换 |
| C | 清除本页笔迹（⌘Z 可以恢复） |
| P / L / V | 笔 / 激光笔 / 选择 |
| H | 隐藏或显示工具栏 |
| 空格、→ / ← | 下一页 / 上一页 |
| ⌘Z、⇧⌘Z | 撤销、恢复 |

推荐：第一个键保持「笔/橡皮擦」，这是驱动自带的切换：选着笔时按一下，笔尖变成橡皮，再按一下变回笔。第二个键从「E」改成「C」，用来清除本页笔迹。
带 ⌘、⌃、⌥ 的组合不会触发这些单键功能，比如 ⌘C 不会清除笔迹。

## 要不要自己写驱动

现在不需要：

- 系统事件已经带完整的压感、倾斜和设备信息，不顺主要来自应用侧的处理，改应用收益最大。
- 自己的用户态 HID 驱动要独占设备（和官方驱动冲突，得先卸载官方驱动），需要「输入监控」和「辅助功能」权限，
  还要逐个型号适配报告格式，换来的只是少一层转发。DriverKit 驱动还需要 Apple 单独批准的权限。
- 已经有开源的跨平台方案 OpenTabletDriver，支持 macOS 和多数 XPPen 型号。真要替换官方驱动，优先试它。

如果以后在具体型号上测出官方驱动限制了上报率或压感精度，可以在 XiwoBoard 里加一个可选的「直读数位板」模式
（IOHIDManager 只读、不独占设备），到时按那个型号的报告格式做。
